# Deployment and CI

## Production image

Hookrelay builds with:

```text
CGO_ENABLED=0
```

The production runtime image is:

```text
gcr.io/distroless/static-debian12:nonroot
```

The image contains one statically linked `/hookrelay` executable, runs as the distroless nonroot user, and has no shell or package manager. A different base image requires a concrete runtime, corporate, or supply-chain need. If the selected registry is unavailable under deployment policy, the fallback is `scratch` with explicitly copied CA certificates and a numeric nonroot UID.

## Artifact and architecture

One image contains the server, Admin CLI, generators, version command, and healthcheck command:

```text
hookrelay:<version>
```

The same `/hookrelay` executable provides `serve`, `admin`, `generate`, `version`, and `healthcheck`. This keeps server and client versions aligned and produces one SBOM and security scan.

The only supported container platform is:

```text
linux/amd64
```

No arm64 or other architecture artifacts are built or tested until an explicit platform requirement appears.

The binary embeds version, commit, build time, and dirty state through linker flags. It provides human-readable and JSON version output. Releases use semantic version tags and an immutable `sha-<short-commit>` tag; production uses a semantic tag, commit tag, or image digest rather than relying only on `latest`.

## Docker Compose

The default stack contains:

```text
hookrelay
valkey
```

An `observability` profile adds Prometheus and Grafana. The local Compose stack publishes both hookrelay ports on loopback only (`127.0.0.1:8080` public, `127.0.0.1:8081` administrative); a deployment exposes the public port through its reverse proxy, while the admin port stays bound to loopback or inside the private network. Secret files are mounted read-only. Hookrelay waits for a healthy Valkey.

Local Valkey uses the same core persistence policy as production: a pinned exact version, AOF with `appendfsync everysec`, `noeviction`, a persistent named volume, and a healthcheck. Developers explicitly remove the volume with `docker compose down -v` when they want a clean state.

Local shared secrets live in the ignored directory:

```text
.secrets/
  consumer
  admin
```

Files use mode `0600`, are generated by the hookrelay commands, and are mounted read-only. `.env.example` contains only non-secret configuration. Webhook credentials are created through the Admin API/CLI and stored in Valkey.

The production security settings are:

```text
read-only filesystem
nonroot user
all Linux capabilities dropped
no-new-privileges
no Docker socket mount
read-only secret mounts
admin port not publicly published
stop_grace_period = 35 seconds
```

Writable `tmpfs` mounts are added only for a demonstrated need.

## Container healthcheck

Because distroless has no curl or shell, the binary provides:

```text
hookrelay healthcheck --url http://127.0.0.1:8081/health/live
```

It uses a short timeout, exits successfully only for a 2xx response, prints nothing on success, and writes a safe diagnostic to standard error on failure.

## CI

Required jobs are:

1. `gofmt` verification;
2. unit tests;
3. race-enabled tests;
4. integration tests against the pinned Valkey image;
5. `go vet`;
6. `govulncheck`;
7. `linux/amd64` binary build;
8. production container build;
9. Docker Compose smoke test covering readiness, Webhook Endpoint creation, fixture webhook ingestion, claim, acknowledgement, metrics, and health, plus (from Milestone 2) the failure path: retries, dead-lettering, CLI replay and delivery-state, and startup expiry of a lease left claimed across a restart.

`golangci-lint` is not selected before the first implementation milestone. After real packages exist, the project may add a small stable rule set if it provides value beyond `gofmt`, `go vet`, tests, race detection, and vulnerability scanning.

Compose and CI pin the same exact Valkey release and never use `latest`. Valkey upgrades are isolated changes that run integration and AOF restart/recovery tests. The initial support contract covers one documented minor release line.
